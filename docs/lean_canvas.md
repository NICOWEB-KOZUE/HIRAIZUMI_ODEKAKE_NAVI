## ③ ひとことで言うと

気軽におでかけしやすくなる
行き先と日にちを選ぶと、コミュニティバス・電車・路線バスを乗り継ぐ行きと帰りの時刻と運賃が分かり、そのまま電話もできる

## ④ アプリでできること（Day8 に見せる3つ）

1つ目（最小形）: 「病院／買い物／役場／郵便局・銀行／温泉／平泉駅」の行き先を選ぶと、利用できる移動手段（コミュニティバスやタクシーなど）の名前が画面に出る機能

2つ目: 日にちと時間帯を選ぶと、コミュニティバスと JR・路線バス（一関平泉線）を乗り継ぐ行きと帰りの時刻つき候補が表示される機能（データは `docs/timetable.md`）

3つ目: 「電話する」「時刻を見る」「利用者登録のしかたを見る」といった次のアクションを起こせるボタンやリンクが表示される機能

## 余裕があれば足すこと（時間が余ったら上から足す）

- （やりたいけれど Day8 には入れない機能。時間が余ったら上から足す）

かかりつけ医の登録: 一関・水沢の個人病院は数が多く全部は調べられないため、本人（または家族）に1つ登録してもらい、受付に間に合うかを判定する。画面の案は `docs/screens.md` の5

町の中心どうしの移動（例: 役場 → ジョイス）でバスの便を探す: 便ごとに町の中心を回る順番が違い、探す処理が複雑になるため。Day8 までは「歩くかタクシー」と出す

福祉有償運送や観光向けバス（るんるん、げいび渓線）の個別ダイヤ詳細: 情報が多すぎて17時間以内での画面設計と実装が終わらないため（時刻つきの乗り換えは、コミュニティバス・JR・一関平泉線に絞って2つ目に入れた）

画面に何が表示されていればできたと言えるか

1つ目: 画面上で選んだ行き先に対応する移動手段の一覧がテキストで表示されていること

2つ目: 選んだバス停・日にち・時間帯に合わせて、「バス停 → 平泉駅 → JR または路線バス → 一関（水沢・衣川）」の行きと帰りの時刻と運賃が画面に並んで表示されていること

3つ目: 各手段の横に「電話する」「時刻を見る」といったタップできるボタンやリンクが配置され、最初のバス停を選ぶ画面にコミュニティバスの「利用者登録が必要です」とリンクが出ていること

初めての人には時間がかかりそうなことへの事前の調べもの

外部APIや複雑なデータベースを使わず、Flaskのルーティングと静的なHTMLテンプレートだけで画面遷移とデータの受け渡しを完結させる方法を確認しておくこと

時刻表データ（`data/` の JSON ファイル）を Python の `json` で読み込み、「この時刻より後の一番早い便」を探す方法を確認しておくこと

祝日を `jpholiday` ライブラリで判定する方法（`pip install jpholiday`、`jpholiday.is_holiday(日付)`）を確認しておくこと

選んだバス停やかかりつけ医を JSON ファイルに保存して、次に開いたときに読み込む方法を確認しておくこと

## AI との対話で変えたこと（Day6 に書く）

- AI の指摘: コミュニティバスは曜日と便が限られ、病院の受付締め切りに間に合わない場合がある
  - 反映した: 駅から病院までのバスと受付時間も調べ、間に合わないときは「受付に間に合いません」と出してタクシーを候補にする形にした
- AI の指摘: 一関・水沢の個人病院は数が多く、全部は調べきれない
  - 反映した: 大きな病院4つは名前で登録し、個人病院は「一関駅周辺」などのエリアで選ぶ形にした。かかりつけ医の登録は「余裕があれば足すこと」に回した
- AI の指摘: 予約が必要な移動手段がないので、「予約ページを開く」ボタンはいらない
  - 反映した: ボタンを「電話する」「時刻を見る」に絞り、運賃とコミュニティバスの利用者登録の案内を足した
- AI の指摘: 現在地（GPS）から検索すると、位置情報の許可や全バス停の位置データが必要になり難しい
  - 反映した: 出発地は「自宅のバス停」と、どの便も通る町の中心5か所（平泉駅・役場・ジョイス・道の駅・町民温泉）から選ぶ形にした
- AI の指摘: 万歩計は Web アプリからスマホの歩数を読めないため、作るのが難しい
  - 反映した: 万歩計はやめて、楽しく使えるように「いっしょに出かける犬」を全画面に出し、結果画面では犬が道のりを歩く形にした。画面の言葉は言いかえず（分かりにくくなる人がいるため）、犬がしゃべるのは出発と到着の2回だけにして、ふつうのことばで短く言う。歩数の目安を出す機能は Day8 のあと
- 余裕があれば足す方に回した機能: かかりつけ医の登録、町の中心どうしの移動でバスの便を探す機能
